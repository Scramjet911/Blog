There is a new beast in the house!!! You need to stop being afraid of the behemoth called AWS... I considered it to be an untameable beast, something good to see from a distance.
To change this I took up a project (more like an assignment) to build a fullstack coffee finder app and deploy it to AWS. Well the first part is easy, since there are no customer requirements, I can just build a barebones express, nodeJS server. The app would be made in react for sure...

So let's start hacking

Starting with what you are not familiar with, is always the best idea, since you can speed up the part you know towards the end. So I began with the backend.

Well the backend is a (simple) express CRUD app. I used MongoDB for the free hosting and sped up boilerplate things with LLM's and decided to use a REST api, I'll try out graphql backends in the next project.

Okay so now that's setup let's figure out the hosting part. Now for someone new to AWS you need a few things:
- A will to live (can't have you giving up on life because of the number of options)
- Random decision making you will regret in the future

But man, does AWS have a lot of options. If the religion of decision paralysis had a god, that would be AWS. Oh, you want a server? Do you want a plain one? With a load balancer (Elastic Load Balancer)? Without? A totally managed instance with autoscaling (Elastic Beanstalk)? A server running containers (Elastic Container Service)? 
<img src = "{{ site.baseurl }}/assets/images/aws_options.png" style="width: 700px;"/>  

Jokes apart, I wanted to stay within the free tier since I had heard a lot of horror stories on reddit about bills of thousands of $$ racking up unintentionally.
But horror stories are just that... Stories. Only after deployment (I decided on Beanstalk) and using the server a bit did I realized that it's pretty easy to stay within the usage limits, (if you don't have infinite loops that is).

Now that I had deployed the server on beanstalk, I realized that one needs a secure connection to consume the api in the frontend. So I need to generate a certificate for the aws url or buy a domain and use that in aws.
I wanted to avoid buying a domain till I finalized on a name for it, but always planning and not executing has been my achilles heel. So time to change... and
I bought a domain!!!! `zephix.org`

So my api will live at `api.zephix.org` and the site can live in `coffee.zephix.org`. I can make as many subdomains as I want now 🔥🔥🔥🔥

But to deploy the frontend, you need to make it first... It had been sometime since I started a new project and I came to a horrifying (not really) conclusion: CRA (create-react-app) is dead, the new king is Vite! And it is bloody fast.
Some hacking (and LLM usage) later TADA!! You've got a fullstack app (No thanks to my epic skills)...

I got ghosted (as usual), but it was nice working with you - AWS..
